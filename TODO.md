# TODO по итогам аудита GophKeeper

Аудит охватывает текущие Go-модули `auth` и `shared` и обязательные сценарии из [спецификации](docs/Specifications.md). P0 блокирует воспроизводимую сборку или безопасное использование аутентификации. P1 блокирует выпуск менеджера паролей.

## P0 — сборка, аутентификация и доступность

- [ ] **Сделать сборку воспроизводимой.** Корневой [Makefile](Makefile#L3) ссылается на отсутствующие каталоги, [auth/go.mod](backend/services/auth/go.mod) не разрешает локальный модуль `shared` самостоятельно, а [shared/go.mod](backend/services/shared/go.mod) не объявляет Gin и bcrypt. Кроме того, [router.go](backend/services/auth/internal/transport/http/router.go#L11) вызывает инжектор, доступный при обычной сборке только после генерации Wire. Настроить разрешение модулей и включить генерацию в сборку либо заменить её явной сборкой зависимостей. Критерий готовности — `make build` и `make test` работают из чистого checkout по документированной процедуре.
- [ ] **Убрать встроенный ключ подписи JWT и его вывод в журнал.** [wire.go](backend/services/auth/internal/transport/http/wire.go#L13) задаёт фиксированный ключ, а [jwt/service.go](backend/services/auth/internal/transport/http/jwt/service.go#L18) пишет в журнал структуру с этим ключом. Загружать стойкий ключ из конфигурации секретов, завершать запуск с ошибкой при отсутствии ключа и исключить его из журналов. Если сервис уже использовался с таким ключом, сменить его и аннулировать ранее выданные токены.
- [ ] **Реализовать проверку JWT до подключения защищённых маршрутов.** [Parse](backend/services/auth/internal/transport/http/jwt/service.go#L49) всегда возвращает успех. Сейчас маршруты только выдают токены. Проверять подпись, допустимый алгоритм, обязательный срок действия и идентификатор пользователя. Настроить короткий срок действия вместо текущих 100 часов и добавить тесты принятия действительного токена и отклонения недействительного.
- [ ] **Устранить гонки в хранилище пользователей.** [memory.go](backend/services/auth/internal/infrastructure/repository/memory/memory.go#L20) читает и изменяет общую map без синхронизации. Параллельные запросы могут нарушить уникальность логина или аварийно завершить процесс. Обеспечить атомарность проверки уникальности и вставки, а также синхронизировать чтение. Критерий готовности — параллельные тесты под `go test -race` и ровно одна успешная регистрация для одинакового логина.

## P1 — обязательные работы до выпуска

- [ ] **Защитить HTTP-вход и унифицировать ошибки.** [app.go](backend/services/auth/internal/app/app.go#L11) поднимает HTTP-сервер без явных таймаутов, а [обработчики](backend/services/auth/internal/transport/http/handler.go#L23) читают JSON без лимита тела. Настроить TLS или документировать обязательный TLS-прокси, задать таймауты и лимит тела, ограничить частоту входа и регистрации. В [MapError](backend/services/auth/internal/transport/http/map_error.go#L11) возвращать 400 для некорректного JSON, 409 для дубликата и единый 401 для неверных учётных данных. При входе отличать отсутствие пользователя от сбоя репозитория, который сейчас маскируется в [VerifyUser](backend/services/auth/internal/usecase/verify_user.go#L46). Обрабатывать ошибку запуска в [main.go](backend/services/auth/cmd/main.go#L5) с ненулевым кодом выхода.
- [ ] **Добавить постоянное хранилище и реализовать обязательные сценарии продукта.** Память процесса теряет учётные записи при перезапуске. Ввести миграции, стабильные идентификаторы и уникальность логинов на уровне БД. В текущем дереве также отсутствуют CLI и серверные операции хранения и синхронизации приватных данных. Реализовать их после исправления аутентификации, с шифрованием данных и проверкой владельца на каждой операции. Проверить сохранность после перезапуска и изоляцию данных между пользователями.
- [ ] **Добавить автоматические тесты и рабочий CI.** В Git нет `*_test.go`, ручные HTTP-примеры используют пустой пароль, а [файл проверки](.github/workflow/golint.yaml) пуст и находится вне `.github/workflows/`. Начать с тестов хранилища, HTTP-ответов и проверки JWT. В CI запускать сборку, `go test -race` и проверку покрытия обоих модулей. [Спецификация](docs/Specifications.md#L57) требует не менее 80% покрытия всей системы.

## Результат проверки

`go test ./...` для `shared` завершился ошибками из-за необъявленных зависимостей. Для `auth` запуск в офлайн-режиме остановился на загрузке зависимостей. Выводы о поведении HTTP и JWT основаны на чтении кода.
